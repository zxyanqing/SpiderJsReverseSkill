# 自主选择验证方式

什么时候读本文件：选择验证方式、理解回归矩阵，确认本地检查与网站验收如何区分，或按 **三状态 / 三维度 / 验收等级** 汇报时。本文件是验收等级（含默认 L2）的唯一权威定义。

本地 fixture 验证工具和实现的局部行为；网站接受只有目标网站反馈能证明。离线任务记录未网站验收。

本地和在线测试都能发现问题、帮助定位原因和验证修复。agent 按待解决疑问、可获取证据及预期信息价值，自主选择测试方式、顺序和粒度；可以交替，也可以仅采用当前有效的一种。需要证明真实消费方接受时取得其实际反馈。测试选择服务于补环境目标，不按联网与否衡量进展，不把离线全通过设为在线前置。授权规则见 `SKILL.md`。

本地检查或工具通过不等于网站接受。每次检查说明它排除了什么或留下什么；修复后仍被拒绝时，回到 `references/env-debug-loop.md` 比较候选解释（含「被拒后总复核」）。局部检查全绿也可能与失败原因无关，应复核核心前提和观察范围，而非继续扩大检查矩阵。

## 验证三状态

每个验证阶段须分开汇报（与 `SKILL.md`「三类进展」对照：实现进展↔实现状态、定位进展↔定位状态、接受反馈↔接受状态）：

1. **实现状态**：本地契约是否修复。
2. **定位状态**：候选解释是否被支持、削弱或排除。
3. **接受状态**：真实消费方是否接受产物。

本地测试只能改变前两项，**不能**自动改变第三项。禁止用「脚本执行完 / 无 jsdom 警告 / Cookie 长度正确」代替消费方成功响应。

## 验收三维度

| 维度 | 含义 |
| --- | --- |
| 消费接受 | 实际 HTTP（或任务声明的）消费方是否接受本地产物 |
| 稳定性 | 多个新会话、资源更新或重复运行后是否仍被接受 |
| 数据真实性 | 与浏览器、官方样本或可信来源是否完成核对 |

三维度独立：一个未完成不抹去其它维度已取得的证据；消费方接受 ≠ 浏览器指纹/数据真实性已证明。浏览器不可用时：**不得伪造真实性**；在权威 HTTP 消费方下，接受与稳定性可独立完成并报告，真实性标为 `未验证` 或 `不适用`。

每项任务交付须单列三维度状态；真实性取值：`已验证` / `未验证` / `不适用`。

## 验收等级

完成需要达到任务声明的验收等级；**默认完成标准为 L2（新含义，见下表）**。用户给出的验收条件优先于默认等级。单次接受只算定位进展和接受反馈，不能作为完成依据。

| 等级 | 含义 | 用途 |
| --- | --- | --- |
| L1 | 至少一次消费接受 | 定位/进展用；**不表示完成** |
| L2（**默认完成**）：消费接受 + 稳定性 | 消费接受，且稳定性按下方 **唯一默认判据**（或用户声明公式）达标；**不要求**真实性已验证；交付须单列真实性维度状态 | 一般任务的完成 |
| L3 | 在新 L2 上增加持续窗口 / 资源版本漂移复验等；真实性仍独立标注 | 用户要求，或交付物要长期作为服务运行时 |

**稳定性达标（新 L2 默认唯一判据 — 禁止各自解释）：**

> **默认**：至少 **3 个全新会话均被接受**（不是「3 个里多数通过」），且其中 **至少一次** 使用当时重新获取的资源。  
> **用户可另行声明**成功率阈值或会话数（任务输入优先）；未声明时一律用上述默认，不得改写为「3 次尝试中有成功即达标」。

3 个会话的默认值与在线护栏 G2（每轮最多 30 次验证请求）相容，见 `references/workflow.md`「预算、护栏与路线退出」。L2 的多会话复验计入 G2 请求预算；触发 G3 停止信号时立即停止复验，并如实报告当前已达到的等级与三维度状态。

### 数据真实性

「被接受」和「拿到真实数据」分开判断。返回 200 且结构正常，不等于数据真实。真实性是独立维度，**不再**与 L2 捆绑；未验证真实性时仍可报告默认完成（L2），但 **禁止**声称与浏览器数据一致。

比对方法：在相近时间、相同查询条件下，比较浏览器拿到的数据和本地拿到的数据，看结构、关键字段、数量级和内容是否一致。无法取得浏览器对照时，记为「数据真实性：未验证」；若消费接受与稳定性已按 L2 判据达标，仍可报告默认完成，但禁止声称与浏览器数据一致。

常见的降级迹象：空列表或固定的少量条目、字段被打码或置零、所有查询返回相同内容、数据明显陈旧——这些影响真实性维度与是否可声称「数据真实」，不自动改写稳定性判据。

### 延迟信号与版本漂移

- **延迟信号**：记录后续请求中的变化，例如验证码出现频率上升、响应变慢、数据变少、账号或 IP 被警告。出现这些变化时，验收等级要降级，并回到定位。
- **版本漂移**：目标资源会轮换时，交付总结中要写明交付物在哪些资源版本（URL、哈希、获取时间）下验证过。

交付时必须写明达到的验收等级、三维度状态及证据，见 `references/records-and-delivery.md`「交付总结」。只达到 L1 时，必须如实写成「单次接受」。声称强风控/传输相关完成时，须记录画像启用层与自洽结论（见 `references/fingerprint.md`「跨层画像一致性」）；缺记录则不得把「单层工具通过」写成完成。

## 通用回归矩阵

| 场景 | 预期 |
| --- | --- |
| 只给 URL、只给 JS、没有成功样本或 Trace | intake 给出可独立动作，不暂停全部工作 |
| 同步结果、导航、Promise、事件、timer、Worker 消息 | 按实际消费边界观察，不套固定等待 |
| API 返回对象后继续调用/读写/绑定事件 | 实现相关契约，不默认空返回或忽略后续差异 |
| 指纹值、配置、会话、随机状态 | 记录来源和可比条件，不把样本固定值冒充通用实现 |
| 外部请求编排、目标 JS 内部 XHR/fetch | 分开选择检查；无内部调用时不要求 XHR/fetch 语义 |
| 旧报告出现网络/Realm 关键词 | 不自动选中当前检查 |
| addon 不可用、可用或 ABI 不匹配 | 依据目标路径选用；必要时才恢复 ABI |
| 目标网站拒绝或不可达 | 如实记录，局部检查不升级为接受 |
| 证据/源码哈希不符、无效 JSON、子进程失败 | 检查报告执行失败，不伪装通过 |

聚合器的 `environment-closure/v4` 状态为 `passed`、`differences`、`insufficient-evidence`、`not-applicable`（逐项）和 `execution-failed`。`--strict` 只对显式选择的当前相关检查生效；网站验收单独记录。命令及配置格式见 `scripts/check_environment_closure.js --help`。

脚本回归使用临时本地 case，不访问目标站点。测试结束保留失败证据所需文件，清理由当前任务决定。

`node --test tests/*.test.js` 运行工具回归及正常/故障配对的诊断样例。`tests/diagnostic-patterns.test.js` 的 HTTP 测试仅绑定本机回环地址，演示本地产物、会话和消费结果的关联，不是第三方网站验收。样例通过不能证明 agent 已经对未知任务实现完全自主纠错；实际任务按其正式路径和反馈判断。

## 自主纠错的评估依据

工具回归与正常/故障样例检查的是工具行为及探针能否区分给定情形。评估 agent 自主纠错时，观察它能否从原始现象自行提出解释、选择实验、发现和修复问题、复验结果，并在局部成功后继续推进总体目标。两类结论分别记录。

评估材料提供目标、可用输入和原始现象，避免预先指定故障位置、修复方案或测试路线。记录实际发生的技术提示和人工介入；已知故障的演示不表述为未知问题的自主发现。测试可在本地、线上或两者结合的场景进行，由 agent 选择；不以是否联网或通过样例的数量代替过程证据。未开展这样的任务执行验证时，明确自主执行效果尚未验证，而不推断原因是缺少在线测试。

## 受控替换与正式路径分别验收

按 `references/controlled-substitution.md` 验证对照有效性、候选来源和匹配、真实命中、目标消费及对应反馈。三组成功仍需判断观察敏感性；只能支持实际覆盖的混合运行结论。局部、混合和完整本地路径结果分别记录，网站返回成功不消除结构或行为反例，也不单独构成 L2 完成。jsdom 普通维护保留受影响回归；结构性统一专项见 `references/dom-state-unification.md`。
