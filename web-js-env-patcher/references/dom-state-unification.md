# DOM 状态来源统一专项

什么时候读本文件：用户要求结构性统一，或证据显示同一语义状态存在多份来源，且当前任务需要统一这一关系时。普通 jsdom 维护和局部修复不进入本专项，只按受影响关系回归。

jsdom 优先与不承担布局/图形/设备读数的边界见 `references/runtime-frameworks.md`。外观层不另存状态，与下文「适配边界清楚」一致；分层原则见 `references/runtime-frameworks.md`「分层原则」。本地检查通过不等于网站接受，见 `references/validation.md`。

## 范围判定

用户的实际任务范围优先。在应用十五项维度前，按请求确定边界：

| 请求 | 适用范围与完成条件 | 历史事项 |
| --- | --- | --- |
| 只审查 | 盘点、复现和报告；不获得修复授权；专项审查才完整对照十五项 | 相关反例保留未完成，范围外单列 |
| 局部修复/普通维护 | 修复当前问题及其受影响状态、入口和消费者；正式组合回归通过即可交付本次局部任务 | 相关历史反例需回归；无关历史问题保留记录，不成为本次必修 |
| 结构性 DOM 统一 | 确定受影响模块/消费者后完整应用十五项、六步方法及完成边界；涵盖声明范围内已有能力与反例 | 不能只取已通过子集、将已知相关反例移出范围来宣布完成；未决范围外问题仍保留 |
| 离线交付 | 依用户要求验证本地执行与声明契约；如果包含统一专项，仍按完整专项验收 | 不强制在线请求；网站接受保留未验收，不由本地通过推断 |

「声明范围」指已确定的专项边界；引用本文件不把一次局部修复自动改写为历史架构统一任务。发现需要更大范围处理的反例时记录其影响，不隐去、不擅自宣告修复。授权规则见 `SKILL.md`。

不同文档、Realm 和会话依实际关系划分，不以实例数量判断来源统一。标准 DOM 与布局、图形、设备读数、会话状态分别判断。

## 验收维度

最终目标仍是原始网站 JavaScript 的本地产物被实际消费方接受。jsdom 已能承担的标准状态直接复用，公开层保留必要的 Realm、身份及接口适配。每项语义状态只有一个权威来源；同一会话与文档内的相关模块共同操作对应底层节点，不把不同文档或 Realm 强行合并。不同语义的关联状态可以分别实现，但必须保持正确的更新、失效、重置和后续消费；必要的后端驱动不等于维护重复页面事实。

验收范围由实际代码、正式入口、既有能力和历史未决事项确定，覆盖相关模块及消费者，不由当前测试的通过范围倒推。保留此前所有验收要求，不扩展为完整浏览器。依据当前网站行为、可核实的标准语义与成熟实现的适用行为判断，不预设参考答案；历史报告作为线索，历史反例逐项核实。

| 验收维度 | 达成标准 |
|---|---|
| **状态归属明确** | 每项语义状态有明确且唯一的权威来源，并能对应到实际字段与读写路径；jsdom 已承担的标准状态不再由其他模块独立保存并决定公开结果。语义不同的状态分别判断，不因存在关联就要求数值相等。 |
| **模块共享真实状态** | 相关模块使用同一组底层节点和权威状态，公开读写实际依托对应节点；共用实例、安装标记或增加副本同步都不能单独证明达成。 |
| **公开入口一致** | 同一状态经不同公开入口创建、读取、修改、查询、删除、替换或恢复默认值，结果符合各入口的实际语义；没有旧字段回退、缓存或备用查询造成的残留值。 |
| **写入统一** | 写入直接作用于指定权威状态，相关模块从同一来源获得变化；不依赖后续读取、定期复制或多个独立存储之间的手动同步维持正确性。给副本补齐同步调用不等于统一来源。 |
| **读取无副作用** | 读取、查询和枚举不修改页面状态，不触发额外变化通知，也不修补此前遗漏的写入。 |
| **变化观察正确** | 变化通知与实际操作对应；不存在漏报、重复通知或同步过程制造的额外通知，记录的状态及顺序符合对照行为。 |
| **对象关系稳定** | 同一底层节点在公开接口中保持应有的身份和关联关系；跨模块使用不会产生互相脱节的节点副本。 |
| **解析与运行接通** | 解析过程操作同一份页面状态；实际解析、暂停、恢复和脚本修改不会互相覆盖。内部解析数据不能成为另一套独立页面状态，普通节点操作通过不能代替解析过程验证。 |
| **适配边界清楚** | 公开包装只承担必要的转换、身份和边界适配；自建状态有具体能力缺口与验证依据。派生缓存可由权威状态重建，失效与重建行为正确，不成为独立决定同一公开结果的第二来源。 |
| **生命周期一致** | 初始化、重置和释放覆盖相关模块，不留下旧状态、失效引用或跨运行污染。 |
| **正式路径生效** | 上述机制在完整初始化后的正式执行路径中实际生效，而非只在单独模块或测试替代路径中成立。 |
| **验证证据充分** | 分别提供状态来源统一的代码路径证据和公开行为符合对照的实验结果；验证覆盖应发生的行为与不应发生的副作用，既有能力没有未经解释的退化。局部行为一致不能单独证明架构统一。 |
| **语义分类准确** | 按实际契约区分标准属性反射、节点关系、布局读数、派生缓存和独立能力状态；保留理由针对该项具体行为。某类能力的缺口不能解释其他标准状态的重复实现，模块归类和状态名称不作为豁免依据。 |
| **关联能力联动** | 状态变化后，关联对象、集合、所属关系、缓存和独立能力后端按契约随之更新、失效或重置；保持应有的公开身份。既验证主状态的即时结果，也验证后续使用，不留下“公开值已变、消费者仍用旧状态”的分歧。 |
| **断言与结论相符** | 每项断言直接验证其声称的结果，比较必要的预期值、对象关系、记录及顺序；记录了某个值不等于验证了它。安装、调用、无异常、局部通过、正式路径通过和消费方接受分别判断，证据不足保留未验证状态。 |

## 方法

1. **确定范围并接续已有成果与未决事项。** 从正式初始化与执行入口确认适用能力，同时纳入声明范围内已实现、已修复和仍未解决的能力及关系，不只验收本次改动或剩余问题。已完成部分保留原验收要求、有效断言和证据，作为持续回归基线；未完成部分核对历史反例，记录原现象、对应验收项、当前复现结果与处置。修复需当前复验；误报或不适用需新证据；未复测、证据不足和暂缓项继续保留。新修复不抵消其他缺口，范围切换不丢失成果或事项。

2. **沿实际读写路径确定状态归属。** 盘点到字段、底层节点、公开入口及关联消费者，逐项说明谁存储、谁读取、谁修改、谁触发关联变化。区分独立语义状态、派生缓存和重复副本；检查备用查询、旧字段回退、初始化资料及非正式分支的实际可达性。保留自建状态需有该项能力的具体缺口依据；缓存需可从权威来源重建并正确失效。名称、模块归类、注释及安装日志不能代替证据。

3. **按完整状态关系完成修改。** 沿“写入入口 → 权威状态 → 公开读取与查询 → 关联对象和后端 → 后续使用”处理同类路径，统一同一语义状态的来源，并接通不同语义状态间必要的更新、清除、失效或重建。发现错误时判断属于来源重复、接口适配、能力缺口还是其他原因，处理同源问题及相关入口，避免只修复暴露问题的一个操作，或因消除同步而破坏必要联动。

4. **分别验证架构与行为。** 用实际代码路径证明来源统一，用独立依据验证公开行为，不能从当前实现反推预期。对适用的创建、读取、查询、枚举、修改、移动、跨上下文迁移、替换、删除、默认值恢复、重置和释放，组合不同入口与顺序，主动构造可能推翻一致性判断的实验，说明不适用项的依据。检查即时结果、对象身份与所属关系、通知和后续使用，并检查不应发生的副作用。验证实际解析暂停与恢复、正式模块组合及生命周期，不能用普通节点操作代替。断言直接比较所声称的值、关系、记录及顺序，区分预期行为变化与无关内部重组；对易产生假阳性的检查确认其既接受正确行为，也能拒绝相关故障。记录字段、调用成功、没有异常或探针命名不能替代有效断言，局部行为通过不能单独证明来源统一。

5. **保留回归能力并核对证据。** 按改动影响复测既有能力，不要求每次重复所有实验。迁移、合并或替换探针时核查原验收含义与覆盖关系仍然保留；新增检查不能挤掉旧检查，放宽断言需独立行为依据。使用旧证据前核对源码版本、配置及执行路径，相关实现变化后重新验证；未重跑与已通过分别记录。既有能力出现退化需查明原因并处理，不能通过删减检查或重新分类隐藏。

6. **逐项验收并继续推进。** 对照“验收要求 → 适用能力与关系 → 代码路径 → 实际断言及结果 → 未决事项”检查全部验收维度。只输出足以支持判断的证据，不以报告长度或检查数量衡量完成。适用项存在反例、未验证关系或证据不足时，报告部分通过及缺口并自主继续修复；确有无法自行解决的阻塞时说明证据和影响。技术优先级可以调整，但不能改变未完成状态。授权规则见 `SKILL.md`。

## 完成判定

本项完成需要：声明范围内所有适用维度均有当前有效证据；已知反例已修复或有依据地排除；相关回归无未解释的退化；没有影响结论的未验证关系。合理的非 DOM 自建能力不因未实现完整浏览器而阻塞本项，但已有相关联动仍需验收。不能用“已覆盖部分通过”宣布整个范围完成。

架构验收与网站接受分别报告。完成本项后继续核对本地产物、实际消费动作和对应反馈，自主选择下一项能推进总体目标的工作，不停留在扩充验收表或重复报告。
