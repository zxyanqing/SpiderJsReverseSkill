# 设计能改变判断的排错循环

什么时候读本文件：设计实验、比较候选解释、判断证据可信度、对照常见差异模式、判断测试假阳性，或约束异步等待与采集时点时。候选问题须按 `references/env-discovery.md` 四类错误分类后再设计实验；静默探测与首轮字段见该文件。

## 从差异到可检验解释

“某接口与浏览器不同”是事实；“这个差异影响当前产物”是解释；“修复后应改变某个被消费的状态”是预期观察。把三者分开，避免每发现一个差异就直接扩建环境。

对下一动作保留少量真正不同的解释，例如：输入/会话不同、执行分支不同、行为错误、输出选取错误、发送过程不同。只记录与证据相关的候选，不为凑数量罗列所有可能。

一个紧凑实验记录可包含：

- 总目标、本动作服务的部分；
- 事实来源、解释及未验证前提；
- 改变项/保持项、观察点、预期结果如何支持或削弱解释；
- 实际结果、实现进展、定位进展、消费方反馈；
- 下一动作与选择理由。

同一契约可以包含方法、返回对象、状态和事件，一次实验可以实现其关联部分。若验证的是一套配置策略，明确整体假设；机械地只改一个字段未必能区分原因。

## 测试反例与假阳性

方法缺失也可能抛 TypeError；因此先确认方法存在及合法接收者调用成功，再检查非法接收者。对象名字相同不能证明构造器、实例与公开原型是同一套。记录一条日志不能证明返回值被目标消费，计数为零也可能是筛选器失效。

用正确行为和故障变体对照同一探针，确认它能拒绝所关心的错误，并接受合法实现。观察相关结果而非实现内部步骤。可检查读写往返、状态变化前后、创建子上下文前后、异步结果交付前后；具体例子见 `references/integration-self-check.md`。

## 失败后如何更新判断

局部修复生效而网站仍拒绝：说明这次整体配置未解决接受，不自动排除该能力，也不说明继续补邻近接口最有价值。三类进展（实现、定位、接受反馈）定义见 `SKILL.md`；分别更新后再选下一动作。

当只有实现进展时，选择能挑战核心前提的实验。可在可恢复副本中比较两个输出边界、某个实际能力分支或替换局部成熟后端；实验使用真实运行结果，不替换原始目标代码来制造期望产物。先明确比较能够说明什么，避免累计多项变化后宣称单因果。

不同新鲜输入无法精确锁定随机/时间时，比较行为约束、状态来源和可观察路径，并说明仍未隔离的因素。没有可比条件的字节变化不是因果证据。

工具错误、观察器影响、被目标捕获的异常与网站拒绝分别检查。选择当前最可能改变判断的观察点；连续同样反馈时重新比较候选，自主决定下一动作。授权规则见 `SKILL.md`。

## 等待与采集时点

异步与生命周期只服务于有证据的完成条件，不为「更像浏览器」改写时序。

### 时间参数四类

权威术语（他处命名须与此一致；不得把 200 ms / 2 s 写成普遍正确值）：

| 类别 | 含义 |
| --- | --- |
| **单脚本执行预算** | 超时上限，用于终止失控执行；**≠** 主动 `sleep` |
| **整个进程期限** | 整次本地运行/子进程的截止时间 |
| **目标结果完成信号** | 有据才等的 Promise / 事件 / Worker / 定时器完成条件 |
| **有限后续观察窗口** | 生成后短暂观察是否被改写；固定窗口 **≠** 正确性证明 |

规则：

- **有据才等**：仅当证据表明目标结果由 Promise、事件、Worker 消息或定时器产生时，才等待对应完成条件。
- **禁止模拟补发**：不得为了模拟而自动补发 `DOMContentLoaded`、`load`，或插入任意固定时长等待。
- **生成边界即采**：识别结果生成边界后立即采集，并保留 **生成时快照**；后续回调变化另记，不覆盖旧候选。
- **固定延迟不是正确判据**：不得用「等 N 毫秒」证明结果正确。
- **同步不被异步覆盖**：同步已生成的挑战结果不得被后续无关异步回调静默覆盖。
- 仅新证据才调观察窗口，并说明观察到什么。

合成回归见 `tests/time-snapshot-semantics.test.js`（T-G5）。与集成侧交叉见 `references/integration-self-check.md`「异步完成与清理」。

## 用浏览器隔离本地能力影响

需要区分某项能力，或主动验证已实现模块时，可采用 `references/controlled-substitution.md`。它规定原生、干预与候选对照及命中—消费—反馈的证据边界；不必先等待失败，也不替代本地状态契约检查。证据无区分力时改变观察或假设，不机械扩充实验数量。

## 证据可信度矩阵

本节用于判断某个环境值、入口结论或参数依赖的可信程度，避免把猜测写成事实。

### 可信度等级

| 等级 | 来源 | 使用方式 |
|---|---|---|
| A | 浏览器真实运行样本、DevTools 断点、Hook 命中调用栈 | 可作为 fixtures 和入口证据 |
| B | HAR / cURL / Network 导出、sourcemap 定位 | 可作为强证据，但需复核动态值 |
| C | 静态搜索、格式化代码、webpack module 名称 | 可作为线索，不单独定论 |
| D | 根据常见模式推断 | 标记为疑似，并说明后续验证方向 |

### 环境值采信顺序

1. 浏览器运行时读取到的真实值。
2. 成功请求样本中携带的值。
3. 页面 HTML / script / meta / window 配置中的值。
4. JS 静态常量。
5. 根据 UA 或平台推断的默认值。

### 输出要求

- 每个关键 source 字段都标注来源等级。
- 不确定字段写“未知 / 待验证”，不要用默认值掩盖。
- Cookie、token、localStorage 敏感值只写键名、用途和脱敏摘要。
- 若结果依赖 D 级推断，不能宣称达到完成所需的验收等级。

## 常见差异模式

| 观察 | 候选方向 | 区分实验 |
| --- | --- | --- |
| 同步无产物 | 异步边界、写入点、入口未触发 | 观察 Promise、事件、导航或网络发送 |
| 返回对象后报错 | 对象方法/属性/状态契约 | 采样返回对象和下一次消费 |
| 本地产物稳定但网站拒绝 | 输入、资源、会话、传输或环境读数 | 保持其余条件，逐项比较 |
| 偶发不一致 | 时间、随机、资源或会话更新 | 在可比输入下重复观察 |
| 仅某个 Realm 失败 | 构造器图、全局、消息/生命周期 | 采集对应 Realm 的运行行为 |

这些是候选假设，不是固定排查顺序。每个结论由目标路径与网站反馈更新。

## 深度环境差异定位

目标在基本运行后仍拒绝且存在环境完整性检测线索时，选取可区分原因的深度对照：Realm、反射、事件顺序、对象内部状态、错误表现或网络时间线。一次只扩大与当前假设相关的观察面。

记录浏览器与本地的具体操作、输入、返回/异常和产物影响。未采集到的维度标为未知；深度矩阵通过不代替网站真实反馈。若连续对照不改变判断，回到目标路径与其他外层变量。

## 静默差异排查

不报错但产物不同或网站拒绝时，检查入口/加载顺序、资源新鲜度、状态来源、异步边界、API 返回对象、随机输入及网络携带数据。每次选择可区分的假设，重跑原始目标路径；泛化“无异常”不能证明环境正确。

## 被拒后总复核

本地能跑但消费方仍拒绝（如 400/412）时，**先按下列顺序复核**，再决定补环境、修会话/传输链或记录外部阻塞。每项标记：已核实 / 被削弱 / 被排除 / 未知，并附证据。未完成本清单前，**禁止**默认「继续扩展 API」。宏观复核入口见 `references/workflow.md`「宏观复核」。

1. HTML、脚本、Cookie、URL 是否来自 **同一次** 挑战会话（原子输入，见 `references/network-session.md`）。
2. HttpOnly Cookie 是否误传给页面脚本，或被脚本输出覆盖。
3. 导航 URL 是否与 **导航发生时** 捕获的 Cookie 配对。
4. Node 是否执行 **原始脚本**，而非诊断改写版本或旧缓存文件。
5. `currentScript`、Realm、原型和函数反射是否可能改变分支。
6. 是否人为补发事件或等待过久，导致状态被后续回调改写（见上文「等待与采集时点」）。
7. Referer、Client Hints、TLS 和页面 UA 是否属于同一画像（见 `references/fingerprint.md`）。
8. 是否取得消费方的 **真实接受证据**，而不是只有 Node 输出。

完成清单后，每轮实验仍应选择能区分候选解释的单变量动作。
