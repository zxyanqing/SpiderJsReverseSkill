# 在浏览器中受控替换本地能力结果

什么时候读本文件：需要在浏览器中隔离某项本地能力的影响，或主动验证已实现模块时。

当需要隔离某项能力对目标结果的影响，或主动验证已实现能力时使用。由 agent 根据问题、可替换边界及信息价值选择；无需先经历失败或通过全部离线检查。它与本地对照、架构自检和正式路径验证并列，不是每轮必做步骤。

## 确定可检验的边界

以真实浏览器承担其他环境，在明确的接口或消费边界换入当前本地实现产生的对应结果，观察目标执行和实际反馈。先说明候选解释、改变项、保持项以及怎样的结果会改变判断。

从目标实际调用、参数、接收对象、操作历史和后续使用确定边界。替换一个返回值只覆盖相应结果路径，不代表整个模块；需要对象身份、原型、品牌、关联状态或后续调用时，评估可保留的契约。Node/jsdom 对象不能直接当作浏览器原生对象传入。

无法保持所需契约时自主改选边界、验证关联能力或采用其他实验，不硬凑全模块替换。多能力存在耦合时按实际关系设计实验，不预设任何模块都可单独隔离。

## 生成与匹配候选

候选必须来自被评估的真实本地实现。可将观察到的调用及状态在本地重放，或在工具与接口契约允许时进行对应本地计算。记录实现版本、配置、输入、初始状态、操作历史和输出边界；匹配上下文、接收对象、参数及状态，调用序号只能辅助匹配。

判断差异前区分标准语义、设备／配置读数和会话动态值。标准语义按适用契约验证；设备与配置可以不同于当前浏览器，不能仅因 UA、图形输出或其他读数不相等就判错。验证声明配置下的行为、相互关联读数的一致性及实际消费反馈；混合时若只替换某个配置相关值，产生的跨能力冲突不能自动归咎本地模块。替换实验里的跨能力冲突 ≠ 已满足交付路径上的跨层画像义务，后者见 `references/fingerprint.md`「跨层画像一致性」。一个本地实现曾在另一配置下成功，也不能直接证明当前浏览器条件下的结论。

动态输入、资源、设备、随机、时间和会话可能改变结果。对照中实际保持了什么、改变了什么、无法控制什么，都应明确。旧样本只有在适用条件得到验证时才能使用，固定值不能冒称本轮计算结果。

传递时保留所需的数据类型、编码、精度、长度、错误及对象包装。同步接口不因跨进程计算变成 Promise；按需要预先生成匹配结果或改选边界。异步接口检查完成顺序和生命周期。不在同一有状态对象上为了比较而额外执行一次有副作用的原生计算；必要时采用独立运行或可重建状态。

匹配失败、回退原生、缓存命中与实际候选交付分别记录，不把静默回退算作本地实现成功。不要替换原始业务判断或伪造最终产物来制造接受。

## 对照与观察敏感性

依据疑问安排以下对照角色，允许复用仍有效的证据，不固定顺序或访问次数：

| 角色 | 执行内容 | 用途 |
|---|---|---|
| 原生基线 | 浏览器原生能力 | 确认当前行为、资源和反馈基线 |
| 干预对照 | 使用相同干预入口，仍交付对应原生结果 | 识别包装、记录、注入和调度的影响 |
| 本地候选 | 在选定边界交付匹配的本地结果 | 检验候选及其与其他能力的组合 |

先核实工具确实支持所需安装时点和上下文，并在独立控制场景检查记录通道确实能观察到已知调用；控制场景的调用不得混入目标消费计数。零日志先区分没有调用与观察失效。调用已发生才安装、漏掉子上下文或无法确认命中，都不能当作有效候选试验。原生基线失败时，仍可研究有效局部差异，但不能据网站接受差异单独归因；干预对照失败时优先检查干预方式。

三组都成功未必说明结果正确：目标可能没使用、未观察到影响，或允许不同结果。必要时使用有契约依据的受控变化检验观察点敏感性；该变化只验证实验，不冒充本地候选，也不假定任意扰动必然导致网站拒绝。观察不敏感时扩大适当观察或缩小结论，而非宣布模块达标。

## 关联命中、消费与反馈

沿本次实验保留足够证据，不要求不可获取的全量跟踪：

- 实验标识、假设、改变项和保持项，以及资源、会话与运行条件；
- 本地结果来源、匹配条件、被替换接口、阶段与上下文；
- 实际命中、交付结果、未匹配、缓存和回退；
- 目标读取、可观察的后续影响、实际请求或导航等消费动作；
- 与该动作对应的响应、页面或业务行为，以及接受条件；
- 干预清理、状态恢复或新上下文隔离情况。

分别判断“已交付”“目标已读取”“观察到行为影响”“本次混合运行被接受”。没有观察到影响不证明没有影响。安装日志、值的打印、无异常、HTTP 200 或截图不能独立串起这条链。

已有日志足够时直接复用，避免为了报告搭建新框架。证据缺失就标明未知，选择补充观察或不同实验；不以表格填写完整代替真实证据。一次有效目标实验须有与结论匹配的对照、候选来源、命中、消费和反馈关联，失败结果也可能具有判别价值。

## 结论与后续行动

| 观察 | 可支持的结论与动作 |
|---|---|
| 有效对照下候选产生差异或失败 | 检查输出契约、输入匹配、状态适配和跨能力一致性；尚未证明单一根因 |
| 各组均成功且候选确实被消费 | 记录包含该候选的混合运行接受事实；不外推为候选数值正确、模块全部正确或唯一因果 |
| 干预对照异常 | 修正实验方式或改选方法，不直接归咎本地模块 |
| 未命中、未消费、静默回退或反馈未关联 | 未检验或未充分检验假设，不能报本地模块通过或失败 |
| 条件不一致或结果波动无解释 | 记录证据不足，选择控制变量、必要重复或不同观察 |
| 单项替换造成跨能力冲突 | 重新检查边界，按实际耦合验证关联契约，限定归因范围 |

按证据继续缩小问题，在已获修复授权的任务中执行“定位 → 修复 → 可比条件复验 → 正式本地路径验证”；只审查任务记录问题及复验要求，不越界修改。没有信息增量时自主改变假设或实验，不无限重复请求或扩建替换框架。授权规则见 `SKILL.md`。

局部输出测试不替代状态来源、公开行为、关联联动和生命周期验收。jsdom 普通维护按影响回归；结构性统一专项见 `references/dom-state-unification.md`。混合运行成功不等于正式本地交付：总体完成仍需正式本地产物、实际消费反馈，并达到声明的验收等级（默认 L2 = 消费接受 + 稳定性，见 `references/validation.md`）。在线记录见 `references/network-session.md`「在线验证记录」。

实验结束清理本次干预，核实后续运行未受污染；诊断浏览器不暗中成为默认交付后端。按需要记录本轮自主选定的下一动作及依据。
