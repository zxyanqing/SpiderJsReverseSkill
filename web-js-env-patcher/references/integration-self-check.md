# 已实现能力的集成自检

什么时候读本文件：改了模块、初始化顺序、Realm 或异步能力，需要做与改动相称的集成自检时；或需要跑最小 DOM 里程碑（节点查询、相对 URL、跨脚本共享、`currentScript`）时。

修改环境模块、初始化顺序、返回对象、跨上下文或异步能力时使用本页。选择受改动影响的关系，不扩成全浏览器规范验收。目标是否消费这些关系决定其对产物的优先级，不决定已实现模块是否值得做基本自检。

## 最小 DOM 里程碑

**范围**：仅验证执行器基础行为的 **受控 fixture**，不是正式挑战页调度规范，也不代表挑战成功或消费方接受。

fixture：本地 HTML + **两段经典同步**页内 `<script>`（无 async/defer/module、非动态插入；走 `runScripts: "dangerously"` 或等价页内路径）。**文档标签顺序仅约束本 fixture。** `outside-only` + 外部 eval **不得**冒充本里程碑通过。资产：`assets/examples/jsdom-dom-milestone.html` / `jsdom-dom-milestone.js`。

强制四项：

1. **节点查询**：能取得页面中的约定元素。
2. **相对 URL**：能基于页面 URL/`baseURI` 解析相对路径。
3. **执行顺序与共享 Realm**：第一段写入的全局可被第二段读取；同一页面 Window/Realm。
4. **`document.currentScript`**：每段 **执行期间** 指向对应 `HTMLScriptElement`（不能只证明「能访问 DOM」）。

四项通过前，不扩展完整浏览器模拟；后续 Cookie/导航/Storage/Worker/指纹等须有目标访问或消费证据。正式页脚本须按原始属性语义调度，见 `references/workflow.md`「脚本执行路径」。不可信内容启用页内执行时同时满足 workflow/runtime 的安全边界。

```bash
node --test tests/jsdom-dom-milestone.test.js
```

## 导航与 Realm 检查

在已通过最小 DOM 里程碑、且任务涉及多脚本或导航提交时，固定核对（与里程碑 fixture 可分开跑）：

1. **跨脚本状态**：初始化脚本创建的全局可被后续外链/入口脚本读取；外链写入可被入口读取。
2. **`document.currentScript`**：每段脚本 **执行期间** 指向对应元素（同里程碑第 4 项语义）。
3. **同 Realm**：页面脚本共享同一页面 Window/Realm，除非原页确有 iframe 等独立 Realm。
4. **导航时点配对**：脚本发起导航时，**立即**捕获该目标 URL 与当时的 Cookie（可见视图及需交接的增量）；写入结构化三元组（见 `references/network-session.md`「Realm ↔ HTTP」）。
5. **禁止用终态回填**：不得用最终 Cookie 覆盖导航时捕获的 Cookie；不得把状态快照中的最终 `location` 自动当作导航目标。

回归应能检出「把导航时状态替换成最终状态」的错误。完整原子输入与 CookieJar 合并细节以 `references/network-session.md` 为准。

## 在真实组合后检查

用正式入口完成模块安装，再获取实际返回对象；创建子上下文后重新检查原上下文。只在独立模块安装后测试，容易遗漏后续覆盖。把公开函数、实例和状态来源放在同一个运行中比较。

例如对一个浏览器观察确认有公开接口的返回对象，依次检查：

1. 公开原型方法存在；
2. 返回实例的公开构造器和原型关系符合该接口观察；
3. 通过公开方法对合法实例调用成功并返回正确对象；
4. 同一公开方法对非法接收者产生预期错误。

不要对所有对象强加同一个 prototype 模型；按接口实际契约选择关系。异常测试同时检查出错位置，避免把“方法不存在”误当作接收者校验成功。

## 子上下文与状态联动

记录父上下文相关函数/构造器，创建子上下文，检查父对象是否意外变化；分别在两端检查函数和错误所属上下文。跨上下文可以共享底层会话数据，公开构造器与包装层是否共享由真实行为决定。

多种入口应读写一致状态。例如属性赋值、属性方法、序列化或集合查询都涉及同一对象时，先改变状态，再通过另一个入口观察；包括替换/移除与必要的失效或重置。单一路径往返通过不足以证明另一入口已接通。

## 异步完成与清理

区分目标定时器、微任务、库内部异步任务、Worker 消息和外部完成条件。队列空、线程启动、脚本返回、结果完成和资源清理是不同事件。

用一个没有无关长定时器“帮忙等待”的最小任务检查：

- 必要回调/消息能否在选定输出边界前交付；
- 对应结果快照是否与消费动作匹配；
- 超时是否保留未完成状态与原因；
- 清理是否发生在必要结果交付之后，清理后是否仍有任务修改已交付状态。

不要等待所有后台任务永远清空；跟踪当前产物必需的完成依据，预算仅用于有界运行。捕获到导航意图后仍需分清状态快照、实际提交和后续任务处理，不照固定时长凑结果。时间参数四类与生成时快照见 `references/env-debug-loop.md`「时间参数四类」。多次 Cookie 写入的候选前缀试验见 `references/network-session.md`「多次写入与候选试验」及 `tests/cookie-candidate-trials.test.js`。

## 观察与验证深度

把自检接入实际初始化和受影响目标路径，检查回归。成熟库通过自己的测试不代表本地桥接、调度和公开接口正确。空错误列表也不代表目标内部捕获异常不存在。

`tests/diagnostic-patterns.test.js` 提供可运行的正常/故障配对例子：公开方法假阳性、初始化覆盖、子上下文污染、状态不联动、异步提前结束，以及本地产物与消费者反馈的关联。运行：

```bash
node --test tests/diagnostic-patterns.test.js
```

这些合成例子解释诊断方法，并非待补 API 清单、目标网站验收或 agent 自主能力证明。

## jsdom 环境的完整验收

普通 jsdom 维护只要求受影响关系回归。结构性统一专项见 `references/dom-state-unification.md`；本页不能替代。检查范围来自正式代码中的状态、入口和消费者，不能由现有探针通过范围倒推。受控替换通过仍不能消除对象关系、通知或状态联动方面的反例。
