# 设备读数与指纹

什么时候读本文件：目标读取 Canvas、WebGL、WebGPU、Audio、字体、DOM 几何等设备相关值；需要区分稳定配置与会话动态状态；属性值来源与成套配置版本；或出现跨层画像、UA/TLS/属地矛盾、Client Hints 与 JS 读数不一致时。

## 设备读数与指纹值

当目标读取 Canvas、WebGL、WebGPU、Audio、字体或 DOM 几何等设备相关值时，区分标准 API 语义与设备/页面具体读数。具体读数可由目标网站观察采样并在可比配置下回放，或由合适的实际运行能力生成；注明来源、长度、哈希、截断和有效条件。

采样缺失时记录证据不足并分析该值是否参与目标产物。未知数据不能写成已观察值。固定样本可帮助局部复现，但跨资源、会话或设备不自动适用。若返回对象随后被调用或读取，需覆盖被消费的契约，而非只补最终字符串。

`check_fingerprint_fixture.js` 用于所选 fixture 的完整性诊断，不代替网站接受。采样 Hook、运行代码与交付代码的职责按任务需求分离。

浏览器采样、固定读数回放与当前本地实现计算分别标注。将本地结果放入浏览器验证时使用 `references/controlled-substitution.md`，匹配输入、状态及操作历史，并验证真实消费；混合路径接受不能证明设备读数唯一正确或完整模块达标。

设备／配置读数与当前浏览器不一致不自动构成错误，相等也不证明整个模块正确。先确认各自声明的配置及关联值是否自洽，再观察适用的消费行为；其他配置下的历史成功不能替代当前输入、状态与反馈证据。

## 配置、会话与动态状态

将语言、时区、UA、Client Hints、screen 等相对稳定配置，与 Cookie/Storage、动态资源、时间、随机输入、事件顺序及单次输出分开记录。比较同一次网站与本地行为时说明哪些来源相同；跨工具、profile 或会话切换时说明可比范围。

稳定配置是画像的 JS/应用层输入；跨层义务见下文「跨层画像一致性」。正式路径须指向具名配置与版本（见「成套配置与版本」）。信息缺失时标为未知；同一输入路径的数据不要从不同会话拼接。哪些字段影响目标产物由运行与网站反馈确认。

## 属性值来源优先级

画像字段按下列优先级取证与注入（禁止把宿主机信息直接暴露为浏览器信息）：

1. **HTTP 头可确定的值** → 优先从请求头推导（如 `Accept-Language`、UA、CH）。
2. **运行配置可确定的时区 / 语言 / 平台** → JS 与 HTTP **统一注入**。
3. **CPU / 内存 / 屏幕 / 插件等** → **禁止**从 Node 默认值（如 `os.cpus().length`）直接推断。
4. **无真实证据** → 标为假设，经单变量实验验证后再采用。
5. **禁止**宿主机信息直接充当浏览器读数。

每个画像字段须标注：**来源**、是否确定、是否假设、与哪些 HTTP / TLS / 时区字段联动。

示例：`Accept-Language: zh-CN,zh;q=0.9` 应对应 `navigator.language === "zh-CN"`，且 `navigator.languages` 按顺序包含 `"zh-CN"`、`"zh"`，而不是只设一个语言字符串。

## 成套配置与版本

UA、Client Hints、TLS impersonation、语言、时区、平台与页面 `navigator` 须来自同一 **具名配置 + 版本**。每次变更记录配置版本与实际生效路径；需要对照时 **成套变更**，避免只改其中一个字段。无法统一或尚未确认的字段标注假设。

每次正式运行须能指出：使用的画像配置名与版本；HTTP / TLS / 时间环境 / 页面 API 值可追溯到该配置；诊断能发现未覆盖或互相冲突的字段。

## 跨层画像一致性

### 定义

**画像**：一次正式交付路径上，向目标/消费方呈现的「像哪一类真实客户端」的稳定信号集合。至少在被实际读写或出站时，下列维度视为同一画像的组成部分（未涉及的维度记「未涉及」，不得填伪证）：

| 层 | 典型信号 | 常见落点 |
| --- | --- | --- |
| A. JS 环境读数 | `navigator`（UA/platform/language）、screen、时区、`userAgentData`、Canvas/WebGL 等设备读数 | 本地运行时 / fixture |
| B. 应用层请求 | Header 中的 UA、`Accept-Language`、Client Hints（`Sec-CH-UA*` 等） | 出站请求 / 会话桥 |
| C. 传输层 | TLS/JA3 类指纹、HTTP/2 行为、所选 TLS 客户端 | 请求客户端 |
| D. 网络与地理语境 | 出口 IP 属地暗示 vs 时区/语言/locale | 代理/直连 + JS 时区语言 |

**义务**：凡同一正式路径上启用了两个及以上层，这些层必须互相吻合，使强风控眼中仍像 **同一台真实设备/同一客户端配置**。只把单层修到「局部检查通过」、组合却矛盾，视为 **实现未完成**（可记定位进展：已发现画像裂隙），不得宣称交付完成。

画像要求的是声明配置 **内部跨层自洽**，不是强迫对齐开发者当前浏览器；「读数与当前浏览器不一致 ≠ 自动错误」仍成立。画像自检通过仍不等于消费接受或默认 L2 完成，见 `references/validation.md`。

### 何时强制核对

满足任一即强制做跨层核对（写入实验记录）：

1. 消费方或目标明显校验传输/指纹/环境组合（拒绝体、challenge、风控字段暗示）。
2. 正式路径同时改动了 A 与 B/C/D 中任一层。
3. 宏观复核时出现「各项局部正常、整体仍被拒」且传输/环境在候选里。
4. 任务或用户明确要求强风控/指纹一致性。

仅本地纯算、无出站、且目标不读设备/UA 类接口时，可整节标不适用。

### 常见矛盾

- JS `platform`/UA 示 Windows，TLS 客户端默认 Node/OpenSSL 指纹或与声明浏览器家族明显不符。
- JS/`userAgentData` 与请求 `User-Agent` / `Sec-CH-UA*` 品牌或主版本不一致。
- `Accept-Language` / JS `navigator.language` 与时区、IP 属地叙事互相冲突且目标可能消费其中多项。
- 图形/音频等设备读数来自配置 X，UA/CH 却声明配置 Y。
- 浏览器取证 profile 与本地回放/出站客户端不是同一声明配置，却当作同一对照。

### 检查顺序

1. 列出本路径 **实际启用的层** 与声明配置 ID（或等价说明）。
2. 对启用层做两两关键字段对照（至少：UA 家族与平台、语言/时区、CH 与 `userAgentData`、TLS 客户端是否匹配声明浏览器）。
3. 有矛盾则先收束画像（改配置、换 TLS 客户端、对齐 header、或缩小未证明的层），再加大在线验证。
4. 记录：启用层、对照结果、修复或「未涉及」；在线仍受 G1–G7 约束（见 `references/workflow.md`）。
