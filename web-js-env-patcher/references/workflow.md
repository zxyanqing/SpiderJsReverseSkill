# 围绕同一目标自主推进

什么时候读本文件：开始或恢复任务、做宏观复核、处理预算与交接、无浏览器条件下本地启动，或区分里程碑 fixture 与正式页脚本调度时。

本文件是工作流程的权威版本。目标是原始网站 JS 的本地产物被实际消费方接受，并达到声明的验收等级（**默认 L2 = 消费接受 + 稳定性**，真实性独立标注，见 `references/validation.md`）；每项观察、修复和测试都说明它服务于该目标的哪一部分。用户明确离线交付时，按该范围完成并区分网站未验收。

## 无浏览器 / 本地启动

**浏览器不是本地运行的前置条件。** 若无法取得浏览器 DOM、远程调试超时或浏览器导航失败，只要已有原始 HTTP HTML、脚本、请求样本或目标消费方，**直接进入本地路径**。浏览器证据是可选对照。只有输入与消费方均缺失时，才将缺证据记为阻塞；不得把「无法取浏览器 DOM」当成 Node 路径失败的结论。

本地启动顺序（页面 Realm 由 **jsdom** 提供；`node:vm` / jsEnv 只作宿主编排，**不替代** jsdom 创建页面 Window/Document）：

```text
原始 HTTP HTML
-> 用 jsdom 创建页面 Window / Document（页面 Realm）
-> 在该页面 Realm 内按「脚本执行路径」执行脚本
-> 按「里程碑规则」或「正式页面规则」调度（二者不同）
-> 采集实际消费边界
-> 将产物交给真实 HTTP 消费方
```

### 脚本执行路径

jsdom 的 `runScripts: "dangerously"`（页内 `<script>`）、`runScripts: "outside-only"` + 外部对 `window` 求值、以及 `getInternalVMContext()` **不保证**相同的加载顺序与 `document.currentScript` 行为，不得写成可任选且等价。

| 用途 | 规定 |
| --- | --- |
| **最小 DOM 里程碑（仅 fixture）** | 权威路径 = **页内脚本执行**：两段**经典同步** `<script>`（无 `async`/`defer`/module、非动态插入），按**文档标签顺序**执行，验证顺序、共享 Realm、`currentScript`。通常对应 `runScripts: "dangerously"`（或行为等价且文档写明的页内 API）。**文档序仅适用于该里程碑 fixture**，不是正式页通用规则。 |
| **正式目标页面** | **不得**「收集所有 script 再按标签顺序串行」。须按原始 HTML 的脚本属性与加载/事件语义：区分经典同步、`defer`、`async`、`type=module`、动态插入等（`async` **无**固定文档序保证）。调度模型见 `references/runtime-frameworks.md`。 |
| **`outside-only` + 外部 eval** | 可用于不依赖 `currentScript` 的受控实验；**不得**当作里程碑第 4 项（currentScript）已通过。 |
| **既有 `jsdom-composition.js`** | outside-only 组合示例，**不满足** DOM 里程碑；里程碑资产见 `assets/examples/jsdom-dom-milestone.html` 与 `assets/examples/jsdom-dom-milestone.js`。 |

### 页内执行安全边界

对不可信或来源未充分信任的页面脚本启用页内执行（含 `dangerously` 或等价）时：

- 必须置于合适的 **OS 级或外部安全边界**（容器、独立沙箱机、明确作业隔离等）。
- **单独子进程**或 **`node:vm` 不是**安全隔离，不得据此声称「已安全」。
- 执行环境 **不得**注入敏感凭证（云密钥、生产私钥等）；会话 Cookie 走私有通道规则（见 `references/network-session.md`）。
- 受控自有 fixture 可在开发机运行，仍禁止把宿主机机密写进页面 Realm；报告区分「受控 fixture」与「不可信页面」。

细则与首跑前约束见 `references/runtime-frameworks.md`；里程碑四项检查见 `references/integration-self-check.md`。

### 无浏览器模式推进路径

```text
静态扫描挑战脚本
-> Node/jsdom 基线运行
-> 记录属性读取、存在性和对象形状检查（见 env-discovery）
-> 对照 Web API 标准契约（结构/行为参考，不凭空给设备画像值）
-> 标记确定值、假设值和未知值
-> 单变量补丁
-> 本地集成回归
-> 真实消费方验收
```

## 启动与恢复

从 URL、JS、请求样本或半成品中取得当前可用输入，尽早跑通一条可观察路径。**不要求先取得浏览器证据。** 恢复时核对实际入口、最近一次真实反馈及证据适用范围。历史报告的事实、解释和下一步建议分开使用；网站变化使哪些假设失效，就重新验证哪些，不按轮次整体推翻或永久保留旧结论。

用简短状态保留：总目标与接受条件、当前事实/来源、候选解释及未验证前提、已试动作、未决差异、下一动作及理由。读取原始证据解决摘要冲突；日志未覆盖的行为保留未知。

## 轮内决策循环

1. 从总体失败回到输入—执行—产物—消费链，确定最值得区分的疑问。
2. 选择当前成本合适的实验，写清预期观察如何支持或削弱解释。不同假设的比较见 `references/env-debug-loop.md`；隔离某项能力影响或主动验证时可选 `references/controlled-substitution.md`，不固定离线／在线顺序。
3. 实现必要契约或调整观察方式；DOM 优先 jsdom（见 `references/runtime-frameworks.md`）。普通维护按受影响关系回归；结构性统一专项见 `references/dom-state-unification.md`。
4. 验证改动在正式入口生效、相关组合关系未退化；模块完成不等于任务完成。按改动使用 `references/integration-self-check.md`。
5. 根据结果自主选择继续修复、本地对照或在线验证；核对实际被消费的产物来自本次本地执行。本地检查不等于网站接受，见 `references/validation.md`。
6. 将实现进展、定位进展和接受反馈分别更新，再选择下一动作。一轮可多次经过此循环，不把一个接口或一次请求当作固定轮次。三类进展定义见 `SKILL.md`。

授权规则见 `SKILL.md`。只在确有无法自行解决的访问条件、业务范围歧义等外部条件时具体说明问题，同时继续不依赖它的工作。

## 宏观复核：何时及如何换方向

触发信号包括：局部修复越来越多但无法解释拒绝；改后总是同样结果且实验无区分力；新增模块破坏已有行为；对照条件长期不一致；局部层检查通过但跨层画像矛盾，或拒绝更像「整机不像」而非单 API；下一步只是继承旧报告。发现这些信号就复核，不等待固定轮数。跨层画像细则见 `references/fingerprint.md`「跨层画像一致性」。

**被拒后固定顺序**：消费方拒绝（含 400/412）且本地脚本仍能跑时，先走 `references/env-debug-loop.md`「被拒后总复核」八项清单；未完成前不把「继续扩展 API」当默认下一步。

依次考虑与当前证据有关的层次，不要求全量检查：

- **目标/消费是否选对：** 当前发送、导航或回调是否真是这份产物的消费点？来源正确与阶段选择正确分别验证。
- **路径是否可比：** 能力存在性、默认返回、异常捕获、会话与资源是否让两端进入不同分支？
- **实现是否自洽：** 正式初始化后的接口、状态和必要异步任务是否互相接通？
- **实验是否有效：** 是否混入版本、时钟、随机、采样/暂停影响，观察器是否改变待测行为？
- **方案是否值得保留：** 继续修补与复用/替换局部后端，哪一个能以更少适配获得有意义的对照？

先找成本低且能改变判断的动作。不要求先证明完整因果链才调查，也不因“尚未证明影响产物”而跳过已实现模块的基本自检。纯基础错误可以修，但与网站拒绝的关系仍标为未证实。

## 输出边界与验证选择

同步返回、Promise、事件、存储更新、Worker 消息、导航或请求发送都可能是边界。观察实际消费者读取的状态，必要时记录各候选边界的输入/产物快照再验证。更晚的值不自动更正确；本地队列空也不等于所有必要任务完成。

本地和在线测试都可帮助发现问题、定位原因及验证修复；依据当前疑问选择探针、正式路径重跑、实际消费反馈或其组合，不按测试地点固定用途、顺序或次数。每次结果都用于决定继续修复、改变解释或检查总体接受条件；局部检查通过和一次在线请求结束都不自动结束工作。在线记录与结论对应的资源、会话、配置、本地产物、实发及响应，具体见 `references/network-session.md`「请求链与会话」。已有在线范围继续有效，技术测试路线由 agent 决定。

## 预算、护栏与路线退出

以下数值均为**默认值**；用户在任务中给出的时间、轮次、请求或站点约束优先。

### 名词

- **一次实验**：有明确预期观察的一次改变、运行和判断。
- **无进展**：一次实验后，实现进展、定位进展、接受反馈三者都没有新增（定义见 `SKILL.md`）。

### 预算与升级

- **B1**：连续 3 次实验无进展，强制做宏观复核（沿用上文「宏观复核」层次）。复核必须产出新的候选解释，或换一种实验类型，不能只是重复上一类动作。
- **B2**：宏观复核后又连续 3 次无进展，或累计 2 次宏观复核仍没有定位进展，写一份进度报告。报告包括：事实、已排除的解释、剩余候选、自选的下一步及理由，以及可选路线和各自代价。写完报告后，继续做不需要用户决策的工作。只有当下一步需要改变交付方式或超出授权范围时，才停下等待用户。
- **B3**：用户给出时间、轮次或请求预算时，以用户为准。

B1、B2 触发的是复核和报告，**不是**等待人工指路；技术选路仍由 agent 决定，报告里必须包含 agent 自己选定的下一步。这与「不按固定失败轮数等待人工指路」相容。

### 在线护栏

- **G1 授权范围**：只对用户任务授权的站点和接口做在线验证，不扩展到同站的其他接口或其他站点。
- **G2 频率**：agent 主动发起、携带本地产物的验证请求，对同一目标站默认间隔不小于 5 秒，每轮不超过 30 次。页面正常加载的子资源不计入。
- **G3 停止信号**：出现 429、封禁或风控升级迹象（验证码难度升级、账号警告、IP 拦截页），或连续 3 次相同拒绝且没有新信息时，立即停止在线验证，回到本地定位，并在记录中写明。
- **G4 账号**：不用用户的真实账号做高频或批量验证；需要登录态时，只使用用户明确提供的账号或会话。
- **G5 副作用**：未经用户对该具体动作明确授权，不执行有业务副作用的操作（下单、支付、发帖、提交业务表单、触发短信或邮件）。
- **G6 付费资源**：未经授权，不调用付费打码平台或其他付费第三方服务。
- **G7 记录**：每次在线验证都记录时间、目标、产物来源和响应摘要；字段与写法见 `references/network-session.md`「在线验证记录」，不另设第二套格式。

### 路线退出

当证据表明本地补环境的代价远超收益时：

- **常见信号**：目标依赖真实布局或 GPU 渲染结果且无法采样回放；依赖真实用户交互（`isTrusted`）且无法建模；资源或 challenge 轮换过快，本地产物有效期极短；同一能力连续更换后端仍无法表达。
- **处理方式**：记录证据和成本估计，提出备选交付方式（例如浏览器后端执行、混合执行、缩小交付范围），并说明各自的代价。
- **决策归属**：交付方式属于用户的范围，改变它需要用户确认。等待确认期间，继续做不依赖该决定的工作。

## 脚本排除（按需）

仅在有明确优化需求时，可对脚本单元做排除对照；先完整基线，每次只跳过一个单元，对照不明或结果变则保留完整执行。方法见 `references/script-exclusion.md`；合成断言见 `tests/script-exclusion.test.js`。非每任务门槛。

## 完成与交接

网站接受目标需要相应实际反馈，并达到任务声明的验收等级（默认 L2：消费接受 + 稳定性，见 `references/validation.md`「验收等级」）。单次接受只算定位进展，不算完成。修好某个接口、生成结果、测试通过或写完报告都不是提前结束总体任务的依据。

用户采用逐轮授权时：轮内持续推进；仍有可执行且能推进目标的动作时继续工作。因用户暂停、执行资源限制或确实无法自行解除的阻塞而结束未完成的一轮时，说明实际停止原因、进展、剩余不确定性、自己选定的下一动作及判别依据，保留可直接恢复的状态。下一轮只需启动授权。确有外部阻塞就准确记录，仍保留可独立推进的工作。没有逐轮约定时，不自行增加新的轮次审批。授权规则见 `SKILL.md`。
